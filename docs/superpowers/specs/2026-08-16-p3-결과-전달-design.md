# P3 결과·전달 화면 설계

작성일: 2026-08-16
상태: 설계 확정 대기
관련: [`api-spec.md`](../../api-spec.md), [`erd-spec.md`](../../erd-spec.md)

## 1. 목적

인식 결과를 환자에게 제시하고, 확인받은 문구를 **주변 사람이 읽을 수 있게**
전달한다.

이 화면의 핵심 문제는 하나다. **모델이 틀린다.** 화자 독립 정확도가 현재
약 0.58이고 목표가 0.70이다. 열 번에 세 번은 틀린 문구를 보여준다는 뜻이다.
결과를 단정적으로 제시하면 오답이 그대로 간호사에게 전달된다.

따라서 이 화면은 **결과를 보여주는 화면이 아니라 결과를 확인받는 화면**이다.

## 2. 신뢰도 3단 분기

`result` 이벤트의 `confidence`는 **선택 필드**다(`api-spec.md` §5).
모델이 제공할 때만 포함된다.

**`confidence`가 없으면 낮음으로 취급한다.** 없는 것을 높음으로 가정하면
가장 위험한 경우(모델이 확신 못 하는데 UI는 단정)가 만들어진다.

| 단계 | 조건 | 화면 |
|---|---|---|
| 높음 | `confidence >= 0.80` | 문구를 96px로 크게, 체크 아이콘, 배경 강조 |
| 보통 | `0.55 <= confidence < 0.80` | 같은 문구, 강조 약하게, 물음표 톤 |
| 낮음 | `confidence < 0.55` 또는 필드 없음 | 문구를 결과로 제시하지 않음 |

### 높음

```
        ✓
   물 주세요
  [ 맞아요 ]  [ 다시 말할게요 ]
```

문구 96px, 성공색 배경. `맞아요`가 주 버튼.

### 보통

```
   이렇게 들었어요
   물 주세요
  [ 맞아요 ]  [ 다시 말할게요 ]
```

문구 96px 유지(읽기 쉬워야 하므로) 하되 배경 강조를 빼고 중립색.
상단에 `이렇게 들었어요`를 붙여 단정이 아님을 드러낸다.
두 버튼의 시각적 무게를 같게 둔다.

### 낮음

```
   잘 못 읽었어요
   다시 한 번 말씀해 주시겠어요?

   ( 혹시 "물 주세요" 인가요? )   ← 작게, 부가 정보

  [ 다시 말할게요 ]   [ 맞아요 ]
```

**추정 문구를 결과 자리에 놓지 않는다.** 32px 부가 텍스트로 내리고,
주 버튼을 `다시 말할게요`로 뒤집는다. `맞아요`는 남겨둔다 — 신뢰도가 낮아도
맞을 수 있고, 반복해서 실패하는 환자에게 탈출구가 필요하다.

## 3. 임계값은 변수다

**0.80 / 0.55는 현재 근거 없는 숫자다.**

모델을 붙인 뒤 검증셋에서 "confidence가 이 값 이상일 때 실제 정답률"을 재서
조정해야 한다. 재는 방법:

1. 검증셋 전체를 추론해 `(confidence, 정답 여부)` 쌍을 모은다.
2. confidence를 구간별로 나눠 각 구간의 실제 정확도를 계산한다.
3. 실제 정확도가 0.90을 넘는 지점을 "높음" 하한으로 잡는다.
4. 실제 정확도가 0.50 아래인 지점을 "낮음" 상한으로 잡는다.

이 작업 전까지 0.80/0.55는 임시값이다. Figma에서는 **변수로 정의**해
나중에 한 곳만 바꾸면 되게 한다.

모델이 `confidence`를 아예 제공하지 않기로 결정되면, 이 화면은 전부
"낮음" 분기로만 동작한다. 그 경우 P3 설계를 다시 봐야 한다.

## 4. 전달 화면

`맞아요` 확정 시 진입한다. **주변 사람이 읽는 화면**이다.

```
┌──────────────────────────┐
│                          │
│       물 주세요            │   ← 화면 전체, 최대 크기
│                          │
└──────────────────────────┘
       화면을 누르면 처음으로
```

- 문구를 화면 폭에 맞춰 최대 크기로 렌더링. 최소 160px.
- 고대비(검정 배경 + 흰 글자 등). 병실 조명에서 멀리서 읽혀야 한다.
- **자동으로 사라지지 않는다.** 간호사가 올 때까지 떠 있어야 한다.
- 화면 아무 곳이나 탭하면 P2 IDLE로 복귀.
- 화면 꺼짐 방지(Wake Lock)를 이 화면에서 활성화한다.

문구 길이가 다양하므로(`아파요` 3자 ~ `화장실 가고 싶어요` 9자) 폰트 크기를
글자 수에 따라 자동 조정한다. 짧은 문구를 작게 띄울 이유가 없다.

## 5. 처리 중 상태

`stop` 전송 후 `result` 수신까지의 구간이다. 추론이 서버에서 한 번에
일어나므로 대기가 발생한다.

- 화면 중앙 로딩 인디케이터 + `읽고 있어요`
- 진행률은 표시하지 않는다(서버가 진행 정보를 주지 않는다).
- 이 구간에서도 §5 오류(P2 문서)가 올 수 있다. 오류 수신 시 P2 화면의
  해당 오류 상태로 되돌아간다.

## 6. 데이터 저장

`utterance` 테이블에 자동 저장된다(`erd-spec.md`). UI가 할 일은 없다.
저장 여부를 사용자에게 알리거나 확인받지 않는다.

**단, `corrected_text`가 문제다.** 현재 스키마는 `corrected_text`를
문맥 교정 결과를 담는 칸으로 쓴다. 환자가 `맞아요`/`다시 말할게요`로 준
피드백을 저장할 자리가 없다. `api-spec.md` §5도 "사용자·피드백 필드는
현재 API에 노출하지 않는다"고 명시한다.

이 피드백은 정확도 개선의 직접적 재료다(어떤 문구가 자주 틀리는지, 어떤
환자에게 약한지). **저장 경로를 만드는 것을 P5·P6 전에 검토해야 한다.**
P3의 UI 설계 자체는 이것 없이도 완결되므로 차단 요소는 아니다.

## 7. 이 설계가 요구하는 백엔드 변경

| 항목 | 필요 여부 | 비고 |
|---|---|---|
| `confidence` 항상 전송 | 권장 | 없으면 전부 "낮음" 분기가 된다 |
| 확인 피드백 저장 | 나중 | P3 UI는 없이도 동작. 개선에는 필요 |

## 8. 열린 항목

- 임계값 0.80/0.55 실측 (§3)
- 모델이 `confidence`를 제공하는지 확정
- 전달 화면의 문구 텍스트: `erd-spec.md`의 `phrase_text`는 띄어쓰기가 있다
  (`물 주세요`). 데이터셋 폴더명은 붙여쓰기다(`물주세요`). **표시에는
  `phrase_text`를 쓴다** — 읽기 쉽다. 서버가 보내는 `text`가 이미 그 값이다.
