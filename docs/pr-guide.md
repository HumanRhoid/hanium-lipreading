# PR 가이드

이 문서는 `hanium-lipreading` 저장소에서 Pull Request(PR)를 만들고 리뷰하는 기준을 정리합니다. 본문은 사람이 읽기 쉬운 한글로 작성하되, 브랜치 이름·커밋 타입·명령어·파일 경로는 영어 표기를 유지합니다.

## 1. 기본 원칙

- 모든 기능·수정·문서 변경은 작업 브랜치에서 진행하고 PR로 `develop`에 합칩니다.
- `main`은 배포 또는 발표 가능한 안정 버전으로 유지합니다.
- 데이터 파일, 자체 촬영 영상, AI Hub 원본 데이터, 모델 가중치, 개인정보가 포함된 산출물은 커밋하지 않습니다.
- PR은 “무엇을 바꿨는가”보다 “왜 바꿨고, 어떻게 검증했는가”가 드러나야 합니다.
- 리뷰어가 재현할 수 있도록 실행 명령, 테스트 결과, 스크린샷 또는 로그를 가능한 한 남깁니다.

## 2. 브랜치 전략

| 브랜치 | 용도 | 예시 |
|---|---|---|
| `main` | 안정 버전, 발표·배포 기준 | `main` |
| `develop` | 개발 통합 브랜치, 기본 PR 대상 | `develop` |
| `feature/*` | 새 기능 개발 | `feature/preprocess-roi` |
| `fix/*` | 버그 수정 | `fix/fps-mismatch` |
| `docs/*` | 문서 작성·정리 | `docs/pr-template-guide` |
| `chore/*` | 설정, 의존성, 저장소 관리 | `chore/update-gitignore` |

권장 흐름:

```text
feature/* 또는 fix/* 또는 docs/*
  → PR
  → develop
  → 안정화 후 main
```

브랜치 생성 예시:

```bash
git checkout develop
git pull origin develop
git checkout -b docs/pr-template-guide
```

## 3. 커밋 메시지 규칙

커밋 메시지는 Conventional Commits 스타일에 맞춰 타입을 소문자로 작성합니다.

```text
type: 변경 요약
```

예시:

```text
docs: PR 템플릿과 가이드 추가
feat: 입 ROI 전처리 파이프라인 추가
fix: 라벨 CSV 파싱 오류 수정
```

권장 타입:

| 타입 | 의미 |
|---|---|
| `feat` | 새 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 변경 |
| `refactor` | 동작 변경 없는 구조 개선 |
| `design` | UI/화면 관련 변경 |
| `chore` | 설정, 빌드, 의존성, 기타 관리 작업 |
| `test` | 테스트 코드 또는 검증 스크립트 변경 |

커밋은 너무 크게 묶지 말고, 리뷰어가 변경 의도를 이해할 수 있는 단위로 나눕니다.

## 4. PR 제목 작성법

PR 제목은 타입과 핵심 변경을 짧게 담습니다.

권장 형식:

```text
docs: PR 템플릿과 가이드 추가
feat: 영상 프레임 추출 스크립트 추가
fix: fps 정규화 로직 오류 수정
```

좋은 제목:

- 변경 범위가 바로 보입니다.
- 타입이 명확합니다.
- “수정”, “작업”처럼 모호한 단어만 쓰지 않습니다.

피해야 할 제목:

```text
수정
업데이트
작업한 거 올림
코드 변경
```

## 5. PR 본문 작성 기준

PR 본문은 `.github/pull_request_template.md`의 항목을 채워 작성합니다.

### PR 요약

2~4줄로 핵심 목적을 설명합니다.

```text
- PR 작성 품질을 맞추기 위해 기본 템플릿을 확장했습니다.
- 팀원이 같은 기준으로 테스트 결과와 영향 범위를 남길 수 있도록 PR 가이드를 추가했습니다.
```

### 변경 유형

해당하는 항목에 체크합니다. 여러 유형이 섞이면 가장 중요한 유형을 먼저 생각하고, 필요한 경우 여러 개를 체크합니다.

### 변경 내용

리뷰어가 확인해야 할 파일과 로직을 중심으로 적습니다.

```text
- .github/pull_request_template.md: PR 본문 항목과 체크리스트 확장
- docs/pr-guide.md: 브랜치, 커밋, 테스트, 리뷰 기준 문서화
```

### 영향 범위

기능, 데이터, 모델, API, 설정, 문서 중 어떤 범위에 영향이 있는지 적습니다. 영향이 없으면 `없음`이라고 명시합니다.

### 테스트 및 검증

실제로 실행한 명령을 적습니다. 테스트를 못 했다면 이유를 숨기지 않고 기록합니다.

예시:

```bash
python -m pytest
python scripts/preprocess_sample.py --input data/sample.mp4
```

문서만 바꾼 경우:

```text
문서 변경만 포함되어 코드 실행 테스트는 수행하지 않았습니다.
Markdown 링크와 체크리스트 항목을 로컬에서 확인했습니다.
```

## 6. 리뷰 요청 전 체크리스트

PR을 열기 전에 아래를 확인합니다.

- [ ] PR 대상 브랜치가 `develop`인지 확인했습니다.
- [ ] 작업 브랜치가 최신 `develop`을 기준으로 만들어졌습니다.
- [ ] 불필요한 대용량 파일이 포함되지 않았습니다.
- [ ] `data/`, 모델 가중치, 영상 파일, 개인정보 파일이 포함되지 않았습니다.
- [ ] README 또는 docs 갱신이 필요한 변경이면 문서를 함께 수정했습니다.
- [ ] 로컬에서 가능한 검증을 실행했습니다.
- [ ] 검증하지 못한 부분은 PR 본문에 이유를 적었습니다.

## 7. 리뷰어 체크 기준

리뷰어는 아래 관점으로 확인합니다.

| 관점 | 확인할 내용 |
|---|---|
| 목적 | PR이 해결하려는 문제가 명확한가? |
| 범위 | 하나의 PR에 너무 많은 변경이 섞이지 않았는가? |
| 재현성 | 실행 명령, 설정, 테스트 방법이 충분한가? |
| 데이터 정책 | 민감 데이터·대용량 데이터·가중치가 커밋되지 않았는가? |
| 모델/전처리 | 입력·출력 형식, fps, ROI, 라벨 매핑이 문서와 일치하는가? |
| 문서 | README, 설계 문서, data/README가 실제 변경과 맞는가? |

## 8. 데이터와 모델 파일 주의사항

이 프로젝트는 영상과 얼굴 데이터를 다루므로 데이터 관리가 특히 중요합니다.

커밋 금지 예시:

- AI Hub 원본 데이터
- 자체 촬영 영상 및 이미지
- 전처리된 프레임/입 ROI 이미지
- 학습된 모델 가중치: `.pt`, `.pth`, `.ckpt`, `.onnx`
- 개인정보가 포함된 CSV, 로그, 캡처 화면
- 로컬 경로와 계정 정보가 포함된 설정 파일

필요한 경우 데이터 위치와 사용 방법만 문서에 적고, 실제 파일은 팀 공유 드라이브나 별도 저장소에서 관리합니다.

## 9. PR 크기 기준

가능하면 PR 하나는 한 가지 목적만 다룹니다.

권장 분리 예시:

- 전처리 코드 추가 PR
- 전처리 문서 보강 PR
- 학습 루프 추가 PR
- 데모 UI 추가 PR

한 PR에 코드, 데이터 정책, 모델 구조, UI 변경이 모두 들어가면 리뷰가 어려워집니다. 변경이 커질 것 같으면 먼저 작은 단위로 나눕니다.

## 10. 병합 기준

PR은 아래 조건을 만족한 뒤 병합합니다.

- 대상 브랜치가 `develop`입니다.
- 최소 1명 이상이 변경 내용을 확인했습니다.
- 작성자가 요청한 검증 또는 리뷰어가 요구한 수정이 반영되었습니다.
- 데이터·가중치·개인정보가 포함되지 않았습니다.
- 충돌이 없습니다.

`develop`에 충분히 통합되고 발표·시연 가능한 상태가 되면 별도 안정화 PR을 통해 `main`으로 반영합니다.

## 11. 빠른 예시

```bash
# 최신 develop 기준으로 작업 시작
git checkout develop
git pull origin develop
git checkout -b docs/pr-template-guide

# 파일 수정 후 확인
git status
git diff

# 커밋
git add .github/pull_request_template.md docs/pr-guide.md README.md
git commit -m "docs: PR 템플릿과 가이드 추가"

# 원격 브랜치 push 후 GitHub에서 PR 생성
git push -u origin docs/pr-template-guide
```

PR 생성 시 대상 브랜치는 `develop`으로 선택합니다.
