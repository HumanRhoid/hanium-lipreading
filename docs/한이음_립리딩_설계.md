# 한이음 드림업 — "구순을 읽자" 립리딩 비전 AI 설계서


---

## 1. 개요 · 도메인

음성을 내기 어려운 환자가 **입모양만으로 의사를 전달**할 수 있게 돕는 비전 AI.

- **도메인(확정): 환자 전용 AAC**(보완대체의사소통) — 발성 곤란 환자 대상
- **언어(확정): 한국어 전용**
- **방식(확정): 폐쇄형(고정 문구) 인식** — 자유 문장 받아쓰기가 아니라 핵심 문구 N개 분류
- **예시 문구**: "아파요 / 물 주세요 / 화장실 / 추워요 / 더워요 / 불 꺼 주세요" 등 20~30개

### 왜 이 범위인가 (엎어짐 방지 근거)
1. **기술 난도 ↓** — N개 중 분류는 초심자 팀이 학기 내 완성 가능
2. **데이터 자체 확보** — 팀이 직접 녹화 → AI Hub 승인 안 기다림
3. **데모·사회적 가치 명확** — 멘토 요구("도메인 구체화") 충족
4. **확장 가능** — 코어 동일하게 두고 실시간·자유문장으로 확장

---

## 2. 목표 · 범위

| 단계 | 목표 | 범위 |
|---|---|---|
| MVP | 한국어 고정 문구 N개를 입모양으로 분류 | 오프라인(영상 파일 입력) |
| 확장1 | 실시간 웹캠 인식 | 지연 최적화 |
| 확장2(후순위) | 자유 문장 인식 | CTC + 한국어 LM |


---

## 3. 시스템 구조

```
[입력 영상/웹캠]
  → L2 전처리(프레임화 → 얼굴/입 검출 → 입 ROI 크롭·정렬)
  → L3 모델(시각 프론트엔드 → 시간 모델 → 분류 헤드)
  → L4 후처리(문구 매핑/신뢰도)
  → L5 출력(화면 텍스트 / TTS 음성 / SRT 자막)
```
※ 도메인이 바뀌어도 L2~L4 코어는 그대로 재사용.

## 4. 레이어별 기술 · 목적

### L1 데이터
| 개발 사항 | 기술/도구 | 목적 |
|---|---|---|
| 고정 문구 자체 녹화 | 스마트폰/웹캠 25fps | 즉시 베이스라인, 외부 의존 제거 |
| 매니페스트 | CSV (`clip_path,label_id,label_text,speaker_id,condition,split`) | 일관된 데이터 참조 |
| 화자 분리 분할 | 스크립트 | 일반화 성능 정직 측정 |
| AI Hub 한국어 립리딩 | aihub.or.kr | 규모 확장(병행 신청) |

> **AI Hub 다운로드 전략 (데이터셋 009):** 전체 ~20TB+이며 거의 전부 `원천데이터`(영상, tar당 50~110GB). `라벨링데이터`는 다 합쳐도 ~180GB. → ① 라벨(TL/VL) 먼저 받아 포맷 확인·타깃 문구 클립 탐색 → ② 해당 `원천` tar 1~3개(개당 ~90GB)만 받아 입 ROI로 전처리 후 원본 삭제. **전체 다운로드 금지(시작은 ~100~200GB).** 이 데이터는 일반 한국어 문장이라 사전학습/검증용, 환자 문구는 자체 녹화로 확보.

### L2 전처리
| 개발 사항 | 기술/도구 | 목적 |
|---|---|---|
| 디코딩·FPS 정규화·분할 | ffmpeg | 입력 표준화(25fps) |
| 프레임 I/O·리사이즈 | OpenCV | 프레임 처리 기반 |
| 얼굴/입술 랜드마크 | MediaPipe Face Mesh | 입 위치 자동 검출(가볍고 실시간 가능) |
| 입 ROI 크롭·정렬 | 랜드마크 기준 로직 | 88×88 그레이스케일 등 입력 일관화 |

### L3 모델
| 개발 사항 | 기술/도구 | 목적 |
|---|---|---|
| 시각 프론트엔드 | 3D-Conv + ResNet-18 | 입모양 공간·단기시간 특징 추출 |
| 시간 모델 | BiGRU/BiLSTM(또는 소형 Transformer) | 입 움직임 시퀀스 해석 |
| 분류 헤드 | FC → softmax(N) | 폐쇄형 문구 분류 |
| 전이학습 | ①한국어/다국어 사전학습 백본 우선(없으면 AI Hub 한국어로 자체 사전학습) ②영어 LRW는 폴백 → 어느 쪽이든 헤드만 한국어 문구로 교체 | 적은 데이터로 성능 확보. 전이되는 건 "입모양 보는 능력"(언어 무관)이고, 언어별 매핑(헤드)은 새로 학습. 한국어→한국어가 음소 교집합 문제 없어 최선 |
| 프레임워크 | PyTorch (ROCm, RX 7900 XTX) | 로컬 학습 |

### L4 학습·평가
| 개발 사항 | 기술/도구 | 목적 |
|---|---|---|
| 학습 루프 | PyTorch, CrossEntropy, Adam | 모델 최적화 |
| 실험 추적 | TensorBoard/W&B | 손실·정확도 기록, 팀 공유 |
| 평가지표 | 정확도/Top-3/confusion matrix | 혼동 문구 분석 |
| 데이터 증강 | 랜덤 크롭·밝기·시간 지터 | 과적합 완화 |

### L5 시스템·출력·데모
| 개발 사항 | 기술/도구 | 목적 |
|---|---|---|
| 오프라인 추론 | Python 모듈 | 영상 → 결과 |
| 실시간 추론(확장) | 웹캠 + 슬라이딩 윈도우 | 실시간 처리 |
| 서빙/통신 | FastAPI 또는 소켓 스트리밍 | 모델→앱 연결(소켓은 팀 C 경험과 결 맞음) |
| 데모 UI | Streamlit/Gradio | 빠른 시연 |
| 출력(음성) | pyttsx3 / 클로바 TTS | 인식 문구를 음성 출력(AAC 핵심) |

### L6 인프라·협업
| 항목 | 도구 | 목적 |
|---|---|---|
| 버전관리 | GitHub + 브랜치 전략 | 협업·이력 |
| 환경 통일 | uv + pyproject.toml + uv.lock | 팀 환경 동일·의존성 재현 |
| 데이터 저장 | 클라우드 드라이브 | 영상 용량 관리(git 밖) |
| 문서·기록 | Notion(md) | 설계·보고서 정리 |
