
```python

hidden_dim=300

ema_decay=0.998

```

전처리 상수는 `src/ml/preprocess/normalize.py`에 있다.

```

TARGET_WIDTH x TARGET_HEIGHT    192 x 96        확정
크롭 방식                        닮음 변환 정렬   확정 (e316d85)
```

**세 가지 모두 확정이며 다시 논의하지 않는다.** 프레임 수는 30·45가 떨어지는 것으로
결론났고, 크롭은 2026-08-25에 8화자 3시드로 재서 기준선을 세웠다. 통계는 t 1.19로
유의하지 않으나, 종횡비 왜곡과 고개 기울기를 없애는 것은 값과 무관하게 옳은 방향이라
구조적 이유로 확정했다.

**기준선은 `results/cv192.json`이다.** 이후 실험은 `--baseline cv192`로 견준다.
`base60`은 옛 112×80 규격이므로 규격 비교 목적 외에는 쓰지 않는다.

## 기각 — 효과가 없거나 반대임이 확인됨

- **모델 용량 과잉** — dropout 0.9로 train acc를 0.51까지 떨어뜨려도 val 불변
- **데이터 증강(공간)** — on/off 차이 0.001
- **앙상블** — 시드 3개 확률 평균으로 +0.004. 세 모델이 78.3%에서 같은 답을 낸다
- **연령이 화자 편차의 주된 축** — s06을 세로로 재촬영하자 0.320 → 0.732(+0.412).
  같은 화자 안의 비교라 노이즈보다 훨씬 크다
- **오디오를 직접 학습한 교사** — log-mel + 작은 CNN이 학습 0.923 / 검증 0.210.
  비디오와 같은 화자 과적합이며 더 심하다

위 다섯은 효과가 0에 가깝거나(0.001~0.004) 노이즈보다 훨씬 크다(0.412).
어느 쪽이든 판정이 안전하다.

- **ImageNet 사전학습** — 0.323 → 0.255(−0.068). **단일 측정이라 엄밀히는 미확정**이나,
  도메인이 다르고 방향이 음수라 우선순위를 낮게 둔다.
  **다만 립리딩 전용 사전학습과 혼동하면 안 된다**(미해결 과제 참조)

## 미확정 — 판정할 만큼 재지 못한 것

**아래는 전부 "효과 없음"이 아니라 "모른다"이다.**

| 개입 | 측정값 | 규모 | 표본 |
|---|---|---|---|
| 에폭 80 → 120 | **+0.041** | 7승 1패 | 8화자 3시드 |
| GRU 단방향 | −0.051 | — | 단일 시드 |
| 시간축 증강 | +0.021 | 2승 1패 | s06 3시드 |
| 예측 편향 보정 | +0.001 | — | 단일 측정 |

**에폭 80 → 120은 24런이 전부 끝났고 판정선에 0.001 못 미쳤다.**

```
2화자   +0.024   t 0.66
3화자   +0.044   t 1.70   p 0.127
5화자   +0.048   t 2.29   p 0.084
8화자   +0.041   t 2.97   p 0.021   7승 1패     판정선 0.042
```

짝 t검정으로는 유의하고(p 0.021) 사전 판정선으로는 미달이다. 판정선이
각 칸을 독립으로 가정한 보수적 근사이기 때문인데, 못 넘은 것을 넘었다고
바꿔 말하면 기준을 사후에 옮기는 것이 된다.

**판정을 미루는 진짜 이유는 따로 있다.** +0.041 중 얼마가 저장 기준
부풀림인지 모른다. s01만 보면 마지막 에폭 기준으로 다시 재자 +0.074가
+0.028로 줄었다. 80에폭 24런의 마지막 에폭 값을 wandb `val/acc` 요약에서
받아 양쪽을 같은 기준으로 다시 계산해야 한다. 재학습은 필요 없다.

**시드 편차가 줄었다는 5화자 시점의 기록은 철회한다.** 8화자 풀링
표준편차는 0.0720으로 80에폭의 0.0725와 사실상 같다(분산비 1.01).
s08 한 화자가 같은 설정에서 0.543 · 0.689 · 0.848을 냈다. **폭 0.305다.**

**화자 간 격차는 좁혀지지 않았다**(최고-최저 0.553 → 0.598). 크게 오른 것은
이미 잘하던 s01·s04·s06이고 하위 s05·s09는 +0.031과 +0.005에 그쳤다.

**학습 불안정이 병목인가** — 2026-08-18에 앙상블 결과(+0.004)를 근거로 "아니다"라고
판정했으나, 2026-08-20에 같은 설정 재실행이 0.09 흔들리는 것이 확인되어 **재개방한다.**

## 미해결 과제

### 측정과 방법론

- **같은 시드가 같은 값을 안 낸다** — 위 "측정 정밀도" 참조. 원인 미확정.
  2026-08-25에 `--deterministic` 스위치를 넣었다(기본 끔). **켜고 두 번 돌려
  폭이 좁아지는지 보면 갈린다.** 아직 안 했다. 약 40분
- **저장 기준이 검증 화자를 보고 고른다** — `train.py`가 검증 점수 최고점에서
  모델을 저장한다. 실사용에서는 새 사용자의 정답을 모르므로 불가능한 방식이다.
  cv192 8화자 3시드에서 **저장 편향 +0.024**로 측정됐다(이전 관측 0.037).
  **발표·서류 수치는 마지막 에폭 값을 써야 한다.** 2026-08-25에 `--baseline` 비교도
  마지막 에폭 기준으로 바꿨다
- **저장 기준의 부등호** — `train.py:402`가 `>=`라 동점이면 나중 에폭을 취한다.
  정점 직후는 하락 구간이라 항상 낮은 값을 고른다. `>` 로 바꾸면 해소된다
- **정점의 절반은 정점이 아니다** — cv192 24런 중 7런이 정점=마지막이다. 평평한
  구간의 최댓값 위치를 기록하고 있을 뿐이다. 검증 클립 155개의 유효 표본이 약 32개라
  에폭별 표준오차가 ±0.087이고, 80에폭 최댓값은 그 위쪽 꼬리를 고른다
- **고정 에폭이 화자마다 안 맞는다** — 정점이 전체의 24%~98%에 흩어진다.
  에폭을 늘려도 안 풀렸다. 다만 이를 화자별로 맞추는 것은 위와 같은 이유로
  실사용에서 불가능하다

### 전처리에서 정보를 버리고 있다

- **입 벌어짐이 크롭에서 지워진다** — 닮음 변환은 입 너비를 96px로 고정하므로
  입을 벌려도 가로가 안 변한다. 세로는 남지만 **배율이 입 너비로만 정해져** 벌어짐이
  화면에서 차지하는 비율이 눌린다. **계산으로 유도한 것이고 실측하지 않았다**
- **입력의 74%가 입술이 아니다** — `MOUTH_WIDTH_RATIO = 0.5`가 주석대로 옛 배율에
  맞춘 값이라, 입술 상자가 192×96 면적의 약 26%만 차지한다. 규격을 올렸어도
  이 비율은 그대로다
- **분류 헤드가 시간축을 균등 평균한다** — 짧은 문구는 복제 구간이 60 중 26까지
  가는데(s07 `아파요` 34→60) 그 정지 프레임도 같은 가중치를 받는다.
  attention으로 바꾸면 헤드만 고쳐도 된다
- **랜드마크 21점을 버린다** — `crop_lip`이 매 프레임 검출하고 상자만 쓴 뒤 좌표는
  반환하지 않는다. 좌표에는 크롭이 지운 입 벌어짐이 그대로 남아 있다.
  클립 단위로 정규화하면 얼굴 크기·위치가 지워져 화자 불변에 가까워진다
- **openness 시계열을 버린다** — `trim_to_speech`에 쓰고 폐기한다
- **발화 길이를 버린다** — 리샘플링이 모든 클립을 같은 프레임 수로 만든다.
  문구가 3~8음절로 다양한데 그 단서가 사라진다. s07 실측으로 트리밍 길이가
  34~75프레임으로 흩어지는 것을 확인했다(문구당 1테이크).
  `ClassificationHead`에 `padding_mask`가 구현돼 있으나 **`LipReadingModel.forward`가
  인자를 받지도 넘기지도 않아** 경로 전체가 죽어 있다
- **리샘플링이 복제라 덜컥거린다** — `np.linspace(...).round()`가 가장 가까운 프레임을
  복제하므로 34→60에서 26곳의 프레임 간 움직임이 정확히 0이 된다. 선형 보간으로
  바꾸면 데이터를 안 쪼개고 없앨 수 있다. **미검증**
- **채널 3개 중 2개가 중복이다** — `to_grayscale_clahe`가 흑백으로 만든 뒤 3채널로
  복제한다. 주석에 적힌 이유(ResNet 사전학습 호환)는 사전학습이 기각되며 사라졌다.
  남는 두 채널에 프레임 차분을 넣으면 모델 변경 없이 움직임 정보를 줄 수 있다

### 모델과 학습

- **립리딩 전용 사전학습 미검토** — ImageNet 사전학습이 실패한 것은 도메인이 달라서다.
  립리딩 데이터로 사전학습된 시각 인코더는 축이 다르다. 우리처럼 화자 8명·클립 1234개
  규모에서 통상 쓰는 방법이다. **아직 조사하지 않았다**
- **오디오 증류** — Whisper 디코더에 15문구를 강제로 넣어 `log P(문구|오디오)`를 재고
  softmax로 분포화한다. 우리 데이터로 학습하지 않아 화자 유출이 불가능하고
  클립마다 다른 분포가 나온다. **교사 성능 0.93은 s06 클립 40개에서 잰 값이라
  표본이 작다.** 강제 디코딩이 우리 환경에서 되는지도 시험하지 않았다
- **label smoothing이 개별 검증된 적 없다** — 08-15에서 grad clip · EMA와 묶어
  한꺼번에 도입됐다(0.261 → 0.420). 개별 기여도를 분리한 적이 없다.
  증류와는 정면 충돌하므로(오답 14칸 균일 강제 vs 교사의 칸별 값) 어차피 정리해야 한다
- **검토 없이 굳은 기본값 다섯 개** — `bidirectional=True`, `>=` 동점 규칙,
  코사인 스케줄, `learning_rate=2e-4`, `label_smoothing=0.1`.
  `2e-4`는 배치 조정 때 선형 스케일링 규칙으로 정했는데, 그 규칙은 SGD 전제이고
  우리는 AdamW를 쓴다. Adam 계열에는 제곱근 스케일링이 통례다
- **warmup 미착수** — 2026-08-16이 제안했고 나흘째 그대로다

### 데이터와 오답 구조

- **화자 간 격차** — cv192에서 최상위 0.905, 최하위 0.269로 **0.636 벌어졌다**.
  **화자 독립 시스템에서는 평균보다 중요한 지표**다
- **s05 재촬영** — 새 크롭에서 확대(×1.31)가 사라졌는데도 0.231 → **0.269**에 그쳤다.
  원본이 720×1280으로 유일한 1080p 미만이다. **크롭으로는 못 건진다.** 재촬영 외의
  방법이 보이지 않는다. 같은 축으로 묶었던 s09는 0.424 → **0.755**로 크게 올라
  더 이상 같은 문제가 아니다
- **s07 원인 미상** — 촬영 조건이 정상(552×156)인데 cv192에서도 0.398이다.
  프레임 30→60에서도 +0.012로 거의 안 움직였다. 전처리 트리밍은 정상임을 확인했다
  (15문구 원본의 55~89% 보존, 최소 고유 34프레임). 문서의 조음 방식 추정이 남는다
- **s01·s06만 규격 변경에서 내려갔다** — 다른 여섯은 올랐다. 세로 해상도·배율·촬영
  조건 세 가설이 모두 기각됐다(2026-08-25 §5). **크롭 이미지 육안 비교가 다음 단계**
- **예측이 소수 클래스로 쏠린다** — `숨쉬기힘들어요` 하나가 전체 오답의 21%를
  흡수하고, 7개 문구가 그쪽으로 일방통행한다(반대 방향 0회인 쌍이 7개).
  학습 데이터는 문구당 79~88개로 균형이 잡혀 있어 사전 확률 탓이 아니다.
  원인은 확인되지 않았다
- **혼동 구조가 화자마다 다르다** — 8화자의 1위 혼동이 하나도 겹치지 않는다.
  과반에서 반복되는 것은 `도와주세요 ↔ 토할거같아요`(6/8) 등 셋뿐이다
- **혼동 쌍은 전부 앞부분이 다르다** — 가래/화장실, 간호사/보호자, 더/추.
  **원리적으로 구분 불가능한 쌍은 아직 확인된 것이 없다.**
  문구 교체가 아니라 앞부분을 보게 만드는 문제다
  (2026-08-18 §3.2의 `물`/`불` 서술은 존재하지 않는 문구를 전제로 한 오류이며 철회됨)
- **실질 다양성은 120** — 클립 1,234개지만 화자 8 × 문구 15 = 120 조합이고
  조합당 10번은 거의 중복이다. 검증 쪽에서도 같은 문제가 나타난다 —
  검증 클립 157개의 통계적 힘이 독립 표본 약 32개어치다(이항분포 가정)
- s06 구본(가로 촬영본)이 `data/archive/`에 보관돼 있지 않다
