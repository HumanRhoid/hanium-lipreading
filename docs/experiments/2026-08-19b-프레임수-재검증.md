> 오염됐을 가능성이 크다"고 적었으나 **틀렸다. 철회한다.**
>
> 원인은 오염이 아니라 **측정 자체의 재현 불가**였다. 같은 설정·같은 시드를 다시
> 돌려도 값이 0.09까지 흔들린다.
>
> ```
> 이 문서의 s06 seed 42        0.809
> 새 런타임 · 패치 없음 재실행   0.822    ← 이 문서와 잘 맞는다
> 8화자 확장의 s06 seed 42      0.739    ← 이쪽이 낮은 쪽 뽑기였다
> ```
>
> **이 문서의 수치는 오염되지 않았다.** 다만 아래의 "채택" 판정은 노이즈 바닥을
> 재지 않고 내린 것이라 무효이며, 미확정으로 재분류한다.
> 판정 기준은 [README](README.md)의 "측정 정밀도" 절을 따른다.

## 1. 요약

같은 날 오전에 45프레임을 기각했으나, **60프레임은 통과했다.**

| 설정 | s06 3시드 | 평균 | 폭 |
|---|---|---|---|
| 30프레임 (기준선) | 0.732 / 0.783 / 0.745 | 0.754 | 0.051 |
| 45프레임 | 0.707 / 0.828 / 0.694 | 0.743 | 0.134 |
| **60프레임** | **0.809 / 0.803 / 0.822** | **0.811** | 0.019 |

```
채택선   0.805   →  통과
```

**[2026-08-20 정정]** 이 채택선에는 근거가 없다. 30프레임 3시드 평균에 눈대중으로
여유를 더한 값이다. **노이즈 바닥을 재기 전에 그은 선이다.**

같은 자료를 짝 t검정으로 다시 보면 이렇다.

```
짝 차이   +0.077  +0.020  +0.077
평균 +0.058   SE 0.019   t 3.05   df 2   p 0.18
```

**세 시드가 다 양수인 것은 사실이나 p는 0.05를 못 넘는다. 미확정이다.**

**[2026-08-20 정정]** "편차가 0.051 → 0.019로 줄었다"는 서술도 철회한다.
같은 조건 재실행의 표준편차가 0.0725이므로, 시드 3개에서 폭 0.019가 나오는 것은
운으로 충분히 설명된다. 편차 개선의 증거가 아니다.

## 2. 45프레임은 왜 실패하고 60은 성공했나

**어중간해서 실패했다.**

```
8음절 문구의 발화 구간   57~60프레임 (정적 제거 후)

30프레임   50% 보존
45프레임   75~79% 보존   ← 여전히 잘림
60프레임   거의 100%
```

**문턱이 45와 60 사이에 있었다**는 것이 이 절의 주장이다.

**[2026-08-20 정정]** 45프레임도 "기각"이 아니라 **미확정**이다. 3시드 평균 −0.010,
1승 2패는 노이즈 안이다. 다만 60프레임과 부호가 반대이므로 재검증 우선순위는 낮다.

보존 비율 계산 자체는 발화 구간 측정(2026-08-18)에 근거한 것이며 유효하다.

### 에폭 부족이 아니었다

"45프레임도 에폭이 부족해 두 번째 정점을 놓친 것 아니냐"는 가설은 로그가 기각한다.

```
45프레임 seed 42   정점 54~55  →  25에폭간 하락 (0.718 → 0.707)
45프레임 seed 1    정점 46~47  →  33에폭간 하락 (0.832 → 0.790)
45프레임 seed 7    정점 46~47  →  33에폭간 하락 (0.720 → 0.650)
```

**뒤쪽에 재상승 기미가 전혀 없다.** 넉넉히 지나고도 안 올랐다.

## 3. 오전의 예측이 틀렸다

오전에 60프레임을 말리며 이렇게 주장했다.

> 평균 풀링은 각 프레임에 1/T 가중치를 준다. T를 늘려도 결정적 순간이 차지하는 몫은
> 그대로다. 그러니 60도 안 될 것이다.

**비율 논증만으로는 설명되지 않는다.** 비율이 같아도 **"완전히 놓치느냐 아니냐"에 문턱이
있었다.** 30프레임에서 1.5프레임짜리 단서는 표본 위치에 따라 통째로 빠지지만, 60프레임에서
3프레임이면 확실히 잡힌다.

**[2026-08-20 주의]** 이 설명은 60프레임이 실제로 좋다는 전제 위에 서 있다.
그 전제가 아직 미확정이므로 이 설명도 확정된 것이 아니다.

## 4. 정점이 늦다

```
30프레임 · 45프레임 · 시간축 증강   정점 42~55에폭  (전체의 55~69%)
60프레임                          정점 59~70에폭  (전체의 74~88%)
```

**[2026-08-20 정정]** 8화자 24런에서는 정점이 **38%~100%**로 흩어졌다. 이 절의
"74~88%"는 s06 3런만 본 것이라 일반화되지 않는다. 그리고 에폭을 120으로 늘려도
정점 위치는 61~99에 흩어졌다. **"정점이 늦으니 에폭이 부족하다"는 추론은 성립하지 않았다.**

seed 42는 42에폭에 1차 정점(0.798)을 찍고 49에폭에 0.775로 내려갔다가 59~64에폭에
0.813으로 재상승했다. 이중 정점은 이 프로젝트에서 유일한 사례이며, 코사인 스케줄이
후반에 학습률을 3분의 1로 줄이는 구간과 겹친다.

다만 seed 1·7은 단일 정점이었으므로 **"60프레임의 성질"이라고 단정할 수 없다.**

## 5. 시간축 증강 — 미확정

30프레임 위에서 시험했다. 발화 구간의 75~100%를 무작위로 잘라 다시 30프레임으로
늘리는 방식으로, **말 속도 변이를 흉내낸다.**

| 시드 | 기준선 | 시간축 증강 | 차이 |
|---|---|---|---|
| 42 | 0.732 | 0.796 | +0.064 |
| 1 | 0.783 | 0.809 | +0.026 |
| 7 | 0.745 | 0.720 | −0.025 |
| **평균** | **0.754** | **0.775** | **+0.021** |

짝 t검정으로 t = 0.84, p = 0.49다. **미확정이다.**
비용이 0이고(전처리·모델 변경 없음) 축이 다른 개입과 더해질 수 있으므로 남겨둔다.

### 08-15의 증강 기각과 충돌하지 않는다

| | 대상 | 전처리가 되돌리나 | 결과 |
|---|---|---|---|
| 공간 증강 (08-15) | 밝기·대비·회전·이동·확대 | **되돌림**(CLAHE·lip_crop) | +0.001 · 기각 |
| 시간축 증강 | 프레임 순서·속도 | 못 되돌림 | +0.021 · 미확정 |

08-15가 남긴 **"전처리가 정규화한 축을 흔들면 소용없다"**는 진단이 정확했기에,
정규화되지 않은 축을 찾아 흔든 것이다.

**[2026-08-20 참고]** 이 진단은 크롭이 입 벌어짐까지 정규화해 버린다는 발견과
같은 줄기다. 전처리가 지운 축을 되살리는 쪽(랜드마크 보조 입력)이 다음 후보다.

## 7. `>=` 동점 규칙의 편향 — 세 번 관측

`train.py:365`가 `smoothed >= best_smoothed`라 **동점이면 나중 에폭을 채택한다.**
그런데 `avg`는 3에폭 평균이라 늦게 반응해 **동점 구간이 정점 직후(하락 중)에 생긴다.**

| 실행 | 될 수 있었던 값 | 실제 | 손해 |
|---|---|---|---|
| 45프레임 seed 42 | 0.720 | 0.707 | −0.013 |
| 45프레임 seed 1 | 0.834 | 0.828 | −0.006 |
| 60프레임 seed 42 | 0.815 | 0.809 | −0.006 |

**세 번 다 아래쪽이다.** `>` 로 바꾸면 정점의 첫 값을 잡는다.

**[2026-08-20 주의]** 손해 폭 0.006~0.013은 노이즈(0.0725)보다 훨씬 작다.
성능 문제라기보다 **부호가 한쪽으로만 쏠린다는 구조적 결함**으로 읽는 것이 맞다.
고치는 비용이 한 글자이므로 고치되, 성능 개선을 기대하지는 않는다.

git 이력을 보면 이 부등호는 **평활 도입 전부터 있던 것을 그대로 이월한 것**이다
(`3a3fca0`에서 비교 대상만 `val_accuracy` → `smoothed`로 바꾸고 부등호는 유지).
평활과의 상호작용을 검토한 흔적이 없다. 검토 없이 굳은 기본값 다섯 개 중 하나다.

## 8. 오디오 교사 — 쓸 만하다

원본 mp4의 오디오(48kHz)로 교사를 만들 수 있는지 확인했다.

### 직접 학습은 실패했다

log-mel + 작은 CNN을 화자 독립으로 학습한 결과다.

```
학습 0.923   검증 0.210
```

**비디오와 똑같은 화자 과적합이다.** 오히려 더 심하다. 원인은 셋으로 본다 —
오디오는 정적 제거를 안 해 발화 위치가 화자별로 다르고, mel에 음색이 그대로 담기며,
화자 7명은 음성 쪽 기준으로도 극히 적다.

### 사전학습 모델은 잘 된다

Whisper(small)로 s06 클립 40개를 전사해 15문구 중 최근접으로 채점했다.

```
완전 일치   29/40  (0.72)
최근접     37/40  (0.93)   ← 실제 성능
```

오답이던 것들도 한두 글자 차이였다(`가레가있어요`, `자세히바꿔주세요`,
`화장실갈고싶어요`). **우리 과제는 열린 전사가 아니라 15개 중 고르기이므로 최근접이
올바른 지표다.**

틀린 3개는 전부 3음절 짧은 문구(`추워요` ×2, `더워요`)였다. 비디오에서도 `더워요`가
흡수구였으므로 **짧은 문구가 양쪽 모두에서 약한 것**이 공통 패턴이다.

**[2026-08-20 주의]** 표본이 **s06 한 화자 40클립**이다. 다른 화자에서도 0.93이
나오는지 확인하지 않았다. 증류를 하려면 8화자 전체에서 먼저 재야 한다.

### ImageNet 기각과 혼동하면 안 된다

```
ImageNet 사전학습   정지 사진 분류   →  립리딩과 도메인이 다름   기각 유지
음성 사전학습       음성            →  과제와 도메인이 같음
```

**[2026-08-20 추가]** 이 표에 빠진 칸이 하나 있다.

```
립리딩 사전학습     입술 영상       →  과제와 도메인이 같음    미검토
```

ImageNet이 실패한 것은 사전학습 자체가 나빠서가 아니라 도메인이 달라서다.
립리딩 데이터로 사전학습된 시각 인코더는 별개의 후보이며 아직 조사하지 않았다.

## 9. 다음 회차 과제

**[2026-08-20 갱신]** 아래는 작성 당시의 계획이다. 실행 결과와 현재 우선순위는
[2026-08-20](2026-08-20-60프레임-8화자-확장.md) §10과 [README](README.md)에 있다.

**1순위 — 60프레임을 8화자로 확장.** → 실행됨. 8화자 3시드에서 +0.033,
규격 준수 6명만 보면 +0.052(t 1.98). 방향은 일관되나 미확정으로 남았다.

**2순위 — 오디오 증류.** → 설계가 바뀌었다. 작성 당시 계획한 "Whisper 인코더 위에
15클래스 분류기를 학습" 방식은 **폐기했다.** 우리 데이터로 학습하면 검증 화자를
본 교사가 되어 결과가 부풀려진다. 대신 Whisper 디코더에 15문구를 강제로 넣어
`log P(문구|오디오)`를 재는 방식으로 바꿨다. 학습이 없어 유출이 구조적으로 불가능하다.

**3순위 — 60프레임 + 시간축 증강.** → 미실행.

**보류 — 75·90프레임.** → 유지.

**보류 — 에폭 증가.** → 실행됨. s01·s03에서 +0.024(4승 2패), 미확정.
"정점이 74~88%라 빠듯하다"는 근거는 §4에서 철회됐다.
