## 3. 같은 시드가 같은 값을 내지 않는다

이 회차의 가장 큰 발견이다.

```
s06 · 60프레임 · seed 42   세 번    0.809 / 0.739 / 0.822       폭 0.083
s01 · 60프레임 · seed 42   두 번    0.675 / 0.764               폭 0.089
s01 · 120에폭 · 3시드 평균  두 번    0.767 / 0.815               폭 0.048
```

s01의 두 실행은 **같은 세션 · 같은 데이터 · 같은 설정**이었다. 실행 시각만 다르다.
1에폭 학습 손실부터 다르다(2.7311 vs 2.7334).

### 처음 세운 가설은 틀렸다

처음에는 "08-19b 실험에 시간축 증강 패치가 걸려 있었을 것"이라고 적었다.
**철회한다.** 깨끗한 재실행이 0.822를 냈고, 이는 08-19b의 0.809와 잘 맞는다.
오히려 8-fold 안의 0.739가 낮은 쪽 뽑기였다.

세션 차이라는 가설도 s01 사례로 배제됐다. 같은 세션에서 벌어졌다.

### 원인 — 유력하나 확정은 아니다

증강 시드는 정상이다. `dataset.py:80`이 클립마다 `torch.randint`로 시드를 다시 뽑아
worker까지 재현되게 설계돼 있고 `train.py:230`이 `VideoAugmentation(seed=seed)`를 넘긴다.

그런데 `train.py:31`의 `set_seed`에 **`torch.backends.cudnn.deterministic` 설정이 없다.**

```python
def set_seed(seed):
    random.seed(seed); np.random.seed(seed)
    torch.manual_seed(seed); torch.cuda.manual_seed_all(seed)
```

GPU 합성곱 역전파는 원자적 누적을 써서 실행마다 비트가 다르다.

**다만 이것을 확인하지 않았다.** `cudnn.deterministic=True`를 켜고 두 번 돌려
값이 같은지 봐야 확정된다. 약 40분이면 된다.

### 0.09가 나오는 것은 모델이 예민해서다

GPU가 만드는 차이는 1e-7 수준이다. 그것이 0.09가 되는 것은 증폭 때문이다.

**한 런 안에서도 같은 폭으로 흔들린다.**

```
s01 · 120에폭 · seed 42
  69에폭  0.675
  91에폭  0.766   ← 정점
  120에폭 0.739
```

같은 궤적 위에서 0.091 범위를 오간다. 런 사이 차이와 같은 크기다.

이유는 경계선에 걸친 클립이 많기 때문이다.

```
검증 클립 157개  →  14개만 뒤집히면 0.089
평균 정답 확률 약 0.5  →  살짝만 밀면 넘어가는 클립이 수십 개
```

## 6. 에폭 80 → 120 — 8화자 완료

24런이 전부 끝났다(2026-08-20 10시, 누적 4시간 31분).

| 화자 | 80에폭 | 120에폭 | 차이 |
|---|---|---|---|
| s01 | 0.741 | 0.815 | **+0.074** |
| s03 | 0.561 | 0.534 | −0.027 |
| s04 | 0.769 | 0.853 | **+0.084** |
| s05 | 0.231 | 0.262 | +0.031 |
| s06 | 0.784 | 0.860 | **+0.076** |
| s07 | 0.312 | 0.372 | +0.060 |
| s08 | 0.667 | 0.693 | +0.026 |
| s09 | 0.424 | 0.429 | +0.005 |
| **평균** | **0.561** | **0.602** | **+0.041** |

```
짝 t검정   평균 +0.041   SD 0.039   SE 0.014   t 2.97   df 7   p 0.021
부호 검정   7승 1패                                          p 0.070
사전 판정선 0.042                                 →  0.001 못 넘었다
```

**두 지표가 엇갈린다.**

판정선 0.042는 각 칸이 서로 독립이라 보고 만든 보수적 근사다. 실제로 재보니
짝 차이의 표준편차가 예상 0.059가 아니라 0.039였다. 같은 화자를 짝지으면
화자 고유의 난이도가 상쇄되기 때문이다. **짝 t검정이 이 자료에 더 맞는 통계이고,
그 기준으로는 p 0.021로 유의하다.**

다만 사전에 정해둔 선을 못 넘은 것도 사실이다. 넘었다고 말을 바꾸면 기준을
사후에 옮기는 것이 된다. 그래서 아래 §9의 검증을 거친 뒤 판정한다.

### 시드 편차는 줄지 않았다 — 앞 판단 철회

17런 시점에 "시드 편차가 0.0725에서 0.0445로 줄어든 것으로 보인다"고 적었다.
**틀렸다. 남은 세 화자가 그것을 뒤집었다.**

```
        s01    s03    s04    s05    s06    s07    s08    s09    풀링
120ep  0.073  0.054  0.024  0.031  0.013  0.082  0.153  0.040  0.0720
80ep                                                            0.0725
```

**분산비 1.01이다. 사실상 같다.** 5화자만 보고 쓴 것이 성급했다.
판정선 0.042도 그대로 유지된다.

s08이 특히 심하다. 같은 설정에 시드만 바꿔 0.543 · 0.689 · 0.848이 나왔다.
**폭이 0.305다.** 이 한 화자가 풀링 표준편차의 절반을 만든다.

### 두 가설 중 하나만 남았다

```
A. 에폭이 부족하다              →  5화자에서 +0.048.  지지된다
B. 낮은 학습률 구간이 핵심이다   →  정점이 비례 이동하지 않음.  기각
```

정점 위치가 스케줄 길이와 관계없다.

```
          80에폭   120에폭
seed 42     80       69
seed 1      63       61
seed 7      80       99
```

seed 1은 80에폭 런과 120에폭 런에서 정점이 63과 61로 거의 같은데, 그 지점의
학습률은 2.15e-05와 9.74e-05로 4.5배 차이다. **학습률 수준이 정점을 부르는 것이 아니다.**

### 학습률 곡선의 차이

`CosineAnnealingLR(T_max=epochs)`이라 에폭을 바꾸면 곡선 전체가 다시 그려진다.
시작값과 끝값은 같고 **줄어드는 속도만 다르다.**

```
에폭     T_max=80    T_max=120
  1      2.00e-04    2.00e-04
 40      1.00e-04    1.50e-04
 80      0           5.00e-05
120      —           0
```

120짜리는 중간 구간에서 항상 학습률이 더 높다. 즉 **"높은 학습률로 더 오래 돈다"**이지
"학습률이 낮다"가 아니다.

### 화자 간 격차는 좁혀지지 않았다

평균은 올랐지만 격차는 조금 벌어졌다.

```
            평균     화자간SD   최고-최저
80에폭     0.561     0.216      0.553
120에폭    0.602     0.235      0.598
```

크게 오른 것은 이미 잘하던 s01·s04·s06이고, 하위 s05·s09는 각각 +0.031과
+0.005에 그쳤다. **화자 독립 시스템에서 중요한 축에서는 개선이 없다.**

### 현재 설정 — 조건부 보류

`epochs=80` 유지. 다만 이번에는 이유가 하나뿐이다.

**+0.041 중 얼마가 §9의 저장 기준 부풀림인지 모른다.** s01에서는 마지막 에폭
기준으로 재면 +0.074가 +0.028로 줄었다. 부풀림이 120에폭에서 더 크다면
(s01은 0.007 대 0.053) 이득의 상당 부분이 통계가 아니라 고르기에서 나온 것이다.

**확인 방법이 있고 새로 학습할 필요가 없다.** 80에폭 24런의 마지막 에폭 값이
wandb 각 런의 `val/acc` 요약에 남아 있다. 그것을 받아 양쪽 모두 마지막 에폭
기준으로 다시 계산하면 된다. **그 결과가 +0.042 위에 남으면 채택한다.**

## 7. 정점 위치가 화자마다 흩어진다

24런의 정점 위치가 전체 에폭의 **38%~100%**로 흩어진다.

```
80에폭에서 아직 최고    5런   s01·42, s01·7, s04·1, s06·1, s08·42
50% 이전에 정점        3런   s07·7(39%), s09·42(38%), s09·7(43%)
```

잘린 5런은 전부 상위 4화자(s01·s04·s06·s08)에서 나왔고, 하위 4화자에서는
하나도 없었다. 이 관측이 §6의 에폭 실험으로 이어졌으나 결론은 미확정이었다.

08-19b가 "60프레임 정점은 74~88%"라고 적은 것은 s06 3런만 본 것이라 틀렸다.

## 8. 학습 손실이 이론적 하한에 도달해 있다

```
label smoothing 0.1 · 15클래스의 교차엔트로피 하한

  목표 분포   정답 0.9 + 0.1/15 = 0.906667,  오답 14칸 각 0.006667
  하한 = -(0.906667·ln 0.906667 + 14 × 0.006667·ln 0.006667) = 0.5565
```

```
  1에폭    2.73     = ln(15).  완전한 무지
 26에폭    0.580    train acc 이미 1.000
 80에폭    0.5622
120에폭    0.5606
하한       0.5565
```

**차이 0.004다. 수학적으로 더 내려갈 수 없다.**

### 다만 "그래서 후반이 무의미하다"는 아니다

처음에 "26에폭 이후는 학습 신호 없이 표류한다"고 적었으나 **과했다. 철회한다.**

```
26 → 120에폭
  train loss   0.5836 → 0.5605     0.023만 내려감
  val acc      0.420  → 0.766      0.346 올라감
```

**정확도 상승분의 대부분이 학습 손실이 거의 멈춘 뒤에 일어난다.**
기울기가 작아진 것이지 방향이 사라진 것이 아니다.

정확한 진술은 이렇다 — **최적화 계열 개입(학습률·에폭·스케줄·warmup)은
"얼마나 내려가느냐"를 바꾸지 못한다. 다만 "어디에 도착하느냐"에는 영향을 줄 수 있고,
그것이 일반화를 가른다.** 지난 닷새의 개입이 ±0.05 안에 머문 것과 모순되지 않는다.

### 검증 쪽은 아직 멀다

```
             손실     하한 대비 잔여    평균 정답 확률
학습 클립    0.5606      0.004           0.907
검증 클립    0.920       0.364           0.51
```

정확도 0.873인데 평균 확신이 0.51이다. **간신히 1등인 클립이 많다.**

검증 손실의 진짜 하한은 0.5565보다 높다. 시각적으로 모호한 클립에서는 최적 모델도
확률을 나눠야 한다. 그 잔여를 아직 재지 않았다. 증류 실험의 부산물로 추정할 수 있다 —
오디오까지 듣고도 틀리면 문구 설계 문제이고, 오디오로는 맞는데 비디오로 틀리면
시각 정보 문제다.

## 9. 저장 기준이 검증 화자를 보고 고른다

`train.py`가 검증 점수 최고점에서 모델을 저장한다. 검증 화자는 실사용에서
새 사용자에 해당한다. **그 사람의 정답을 미리 알아야만 가능한 방식이다.**

에폭을 고정하고 끝까지 돌린 값과 비교하면 얼마나 부풀려지는지 나온다.
120에폭 8화자 24런 전부다.

| 화자 | 최고점 저장 | 마지막 에폭 | 차이 |
|---|---|---|---|
| s01 | 0.815 | 0.762 | 0.053 |
| s03 | 0.534 | 0.489 | 0.045 |
| s04 | 0.853 | 0.811 | 0.042 |
| s05 | 0.262 | 0.256 | 0.007 |
| s06 | 0.860 | 0.819 | 0.041 |
| s07 | 0.372 | 0.304 | 0.068 |
| s08 | 0.693 | 0.616 | 0.078 |
| s09 | 0.429 | 0.395 | 0.034 |
| **평균** | **0.602** | **0.556** | **0.046** |

**여덟 화자 전부 부풀려졌다. 방향이 하나도 어긋나지 않는다.**

개별 런에서는 훨씬 크게 벌어진다.

```
s07 seed 1    저장 0.380   마지막 0.216   차이 0.164
s01 seed 1    저장 0.898   마지막 0.764   차이 0.134
s08 seed 7    저장 0.848   마지막 0.715   차이 0.133
s04 seed 1    저장 0.847   마지막 0.760   차이 0.087
```

s07 seed 1은 32에폭에서 0.380을 찍고 끝까지 내려가 0.216으로 끝났다.
**보고된 0.380은 그 화자의 정답을 알아야만 고를 수 있는 값이다.**

### §6의 판정이 이 값에 걸려 있다

에폭이 길수록 점수를 여러 번 재고 그중 최고를 고르므로 부풀림이 커진다.
s01에서 80에폭은 0.007, 120에폭은 0.053이었다.

```
                80에폭   120에폭   차이
최고점 기준      0.741    0.815    +0.074
마지막 기준      0.734    0.762    +0.028
```

**s01만 놓고 보면 에폭 이득의 62%가 고르기에서 나왔다.** 이것이 여덟 화자에서
같은 비율이라면 §6의 +0.041은 실제로 +0.016 정도가 되고 판정선에 한참 못 미친다.

**확인에 재학습이 필요 없다.** 80에폭 24런의 마지막 에폭 값이 wandb 각 런의
`val/acc` 요약에 남아 있다. 받아서 양쪽 모두 마지막 에폭 기준으로 다시 계산한다.

**발표·서류에 쓸 수치는 마지막 에폭 값이어야 한다.** 8화자 평균 0.556이다.

동점 규칙 문제도 같은 자리에 있다. `train.py:365`가 `>=`라 동점이면 나중 에폭을
취하는데, 정점 직후는 하락 구간이라 항상 낮은 값을 고른다. 관측된 손해는
0.006~0.013으로 노이즈보다 작으나 **부호가 한쪽으로만 쏠린다.**

## 10. 전처리가 정보를 버리고 있다

이번 회차에 코드를 읽으며 발견한 것이다. **아래는 계산으로 유도했고 실측하지 않았다.**

### 입 벌어짐이 크롭에서 지워진다

`crop_lip`이 `margin=0.5`으로 입술 상자의 양옆·위아래에 각각 절반씩을 더한다.
그래서 크롭은 가로도 세로도 상자의 2배다. 그리고 상자를 **매 프레임 새로 계산**한 뒤
매번 112×80으로 늘린다.

```
입 다물었을 때   상자 400×80  →  크롭 800×160  →  112×80
입 벌렸을 때     상자 400×160 →  크롭 800×320  →  112×80
```

두 경우 모두 입술이 출력에서 정확히 56×40을 차지한다.
**입을 두 배로 벌려도 화면에서 같은 크기로 보인다.**

립리딩에서 입 벌어짐은 가장 기본적인 단서다. 남는 것은 입 안쪽 모습(어두운 구멍,
이, 혀)뿐이다.

**확인 방법** — 클립 하나에서 프레임별 크롭 세로 길이를 출력해 `openness`와 같이
움직이는지 본다. README 데이터 현황에 "입이 벌어진 정도에 따라 세로가 흔들린다"는
서술이 이미 있어 정황은 맞는다.

### 입력의 75%가 입술이 아니다

같은 이유로 112×80 = 8960픽셀 중 56×40 = 2240픽셀만 입술이다.
나머지는 턱·볼·코 아랫부분이다.

### 이미 계산해놓고 버리는 것 셋

| | 어디서 계산되나 | 어디로 사라지나 |
|---|---|---|
| 입술 랜드마크 21점 | `crop_lip`이 매 프레임 검출 | 상자만 쓰고 좌표는 반환 안 함 |
| openness 시계열 | `crop_lip_frames`가 프레임마다 계산 | `trim_to_speech`에 쓰고 폐기 |
| 발화 길이 | 트리밍 후 프레임 수 | `resample_frames`가 균등화하며 소실 |

**랜드마크 좌표에는 크롭이 지운 입 벌어짐이 그대로 남아 있다.**
클립 단위로 평균을 빼고 크기로 나누면 얼굴 크기·위치·거리가 지워져
화자 불변에 가까워진다. 프레임당 42차원(21점 × 2좌표)이다.

### 채널 3개 중 2개가 중복이다

`normalize.py:16`의 `to_grayscale_clahe`가 흑백으로 만든 뒤 `GRAY2BGR`로 3채널로
복제한다. 주석에 적힌 이유는 ResNet-18 사전학습 가중치 호환인데,
**사전학습은 기각됐다.**

남는 두 채널에 앞뒤 프레임 차분을 넣으면 **모델 변경 없이** 움직임 정보를 줄 수 있다.
파라미터도 텐서 모양도 그대로다.

## 11. 판단

```
60프레임      미확정.  방향은 일관되나 8화자로는 확정 불가
에폭 120      미확정.  계산 1.5배와 편차 악화를 감안해 채택 안 함
```

`normalize.py`의 `FIXED_FRAME_COUNT`는 30으로 두고, 실험은 60 위에서 계속한다.
`epochs=80`을 유지한다.

**이 회차의 실질적 성과는 60프레임 판정이 아니라 세 가지 구조적 발견이다.**

1. 측정이 재현되지 않는다 — 판정 방법론 전체를 다시 세워야 한다
2. 저장 기준이 검증 화자를 본다 — 보고 수치가 약 0.05 부풀려져 있다
3. 전처리가 입 벌어짐과 랜드마크를 버린다 — 입력 자체를 고칠 여지가 있다

## 12. 다음 회차 과제

**1순위 — 전처리가 버린 정보를 되살린다.** 랜드마크 42차원 + openness 1 +
발화 길이 1을 보조 입력으로 넣는다. 이미 계산되는 값이라 전처리 재실행만 필요하다.
크롭이 지운 축을 되돌리는 것이므로 다른 개입과 축이 다르다.

프레임 차분은 더 싸다. 중복 채널 두 개에 앞뒤 차분을 넣으면 전처리도 모델 변경도
필요 없다.

**2순위 — 오디오 증류.** 교사는 **강제 디코딩 방식**으로 만든다. Whisper 디코더에
15문구를 하나씩 넣어 `log P(문구 | 오디오)`를 재고 softmax로 분포화한다.

```
우리 데이터로 학습하지 않음   →  화자 유출이 구조적으로 불가능
클립마다 다른 분포           →  발음이 뭉개진 클립은 퍼지고 또렷하면 뾰족
인코더 1회 + 디코더 15회      →  1234클립에 20~40분. 한 번 계산해 저장 후 재사용
```

기각한 대안 둘:

```
분류기 학습   Whisper 인코더 위에 15클래스 분류기를 우리 데이터로 학습
              → 폴드마다 재학습해야 유출을 막는다. 8배 비용
전사 문자열   Whisper 전사 → 15문구와 철자 거리 → softmax
              → 전사가 정확한 클립에서 분포가 문구별로 동일하다.
                 클립별 정보가 없어 사실상 클래스별 label smoothing에 그친다
```

**교사 성능 0.93은 s06 클립 40개에서 잰 값이다.** 8화자로 먼저 재야 한다.

**3순위 — 립리딩 전용 사전학습 조사.** ImageNet이 실패한 것은 도메인이 달라서다.
립리딩 데이터로 사전학습된 시각 인코더는 별개의 축이며 **아직 조사하지 않았다.**
화자 8명·클립 1234개 규모에서는 이쪽이 가장 큰 지렛대일 수 있다.

**4순위 — 재현성 확정.** `cudnn.deterministic=True`를 켜고 같은 설정을 두 번 돌린다.
값이 같으면 원인이 확정되고 짝 비교가 성립하게 된다. 약 40분.

**5순위 — s05 재촬영.** s05 한 명이 8화자 평균을 0.04 끌어내린다.
**데이터 품질이 알고리즘 개선을 막는 사례**이며 모델 쪽 개입으로는 못 고친다.

**같이 정리할 것 — label smoothing.** 오답 14칸을 균일하게 강제하는 것과 교사가
칸마다 다른 값을 요구하는 것이 정면 충돌한다. 증류 시 끄는 것이 표준이므로
증류 실험에 2×2로 함께 넣는다. 08-15에서 grad clip · EMA와 묶여 도입된 뒤
개별 기여도를 분리한 적이 없다.

**보류 — 75·90프레임.** 60의 값어치가 확정되지 않았다.

**후순위 — warmup · 학습률 재조정.** 여지가 작다고 보나, §8의 정정에 따라
"원리적으로 불가능"은 아니다. 24런 비용을 쓸 만한 기대 효과인지가 관건이다.
