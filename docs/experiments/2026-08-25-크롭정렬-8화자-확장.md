# 크롭 정렬 8화자 확장 · 새 기준선 수립

일자: 2026-08-25
상태: **192x96 닮음 변환 정렬을 기준 규격으로 확정.** 이후 모든 실험은 이 조건 위에 쌓는다

## 1. 요약

`e316d85`에서 바꾼 크롭 방식을 8화자 3시드(24런)로 처음 측정했다. 2026-08-22
문서가 "학습 결과가 하나도 없다"고 적었던 그 변경이다.

| | 결과 |
|---|---|
| 평균 (마지막 에폭) | **0.621** · 중앙값 0.663 |
| 최저 화자 | s05 **0.258** |
| 최고 화자 | s03 **0.892** |
| 옛 규격 대비 | 저장값 기준 **+0.084** (8화자 3시드 평균) |
| 부호 | 5승 3패. **하위 다섯이 오르고 상위 둘이 내렸다** |

**규격은 확정으로 둔다.** 아래 판정 절의 통계는 참고이며, 이 회차의 결과물은
판정이 아니라 **새 기준선(`results/cv192.json`)**이다.

## 2. 무엇을 바꿨나

### 2.1 옛 방식 — 축 정렬 상자

`LIP_LANDMARKS` 21점의 최소·최대로 사각형을 만들고 50% 여백을 붙인 뒤 112x80으로
리사이즈했다. 문제가 넷이었다(2026-08-22 §5.1).

- 고개가 기울면 입이 대각선으로 들어간다
- 상자 종횡비가 화자마다 다른데 112:80에 밀어 넣어 **가로와 세로가 다른 배율로 눌린다**
- 21점에 윗입술 바깥 점이 없어 사각형 윗변이 사실상 입꼬리 높이가 된다
- 입을 벌리면 상자가 커지고 다물면 작아져 발화 중 기준선이 움직인다

### 2.2 새 방식 — 닮음 변환 정렬

입꼬리 두 점(랜드마크 61, 291)으로 좌표계를 잡는다.

```
회전   두 점을 잇는 선을 수평으로          고개 기울기 제거
배율   두 점 사이 거리 = 96px              한 배율만 사용, 종횡비 왜곡 없음
중심   입술 21점 무게중심을 정중앙에
크기   112x80 -> 192x96
```

**핵심은 배율이 하나라는 점이다.** 가로세로가 따로 눌리지 않는다.

부수 효과로 데이터가 2.06배 커졌다. 클립당 1.54MB -> 3.16MB, 전체 2.0GB -> 4.1GB다.

## 4. 판정 기준 둘이 반대를 가리킨다

```
평균 +0.084   판정선 0.042   ->  넘었다
짝 t검정 t 1.19 · df 7 · 5승 3패  ->  유의하지 않다
```

**판정선을 넘은 것은 평균 크기 때문이지 일관성 때문이 아니다.** 화자별 부호가
−0.197에서 +0.331까지 갈려 표준오차가 0.071까지 커졌다. 판정선은 각 칸을 독립으로
가정한 근사라 이런 분산을 반영하지 못한다.

규격을 확정으로 두는 것은 이 통계 때문이 아니라 **2.2의 구조적 이유** 때문이다.
종횡비 왜곡과 고개 기울기를 제거하는 것은 값과 무관하게 옳은 방향이다.

## 5. 화자별 부호를 설명하지 못했다

세 가설을 세웠고 셋 다 데이터와 맞지 않았다.

| 가설 | 왜 기각인가 |
|---|---|
| 세로 해상도 손실 | s03(−28%)이 s04(−15%)보다 많이 잃고도 훨씬 올랐다 |
| 배율(축소 정도) | s08이 x0.28로 s01·s06과 같은 급인데 혼자 +0.238 |
| 촬영 조건 | s01·s06·s08이 모두 1440x1920 얼굴만인데 s08만 올랐다 |

크롭에서 입술이 차지하는 세로 픽셀과 성능 변화의 상관은 **r = +0.27**(8점)로
사실상 없다.

**설명 변수를 못 찾았다.** 위 셋은 계산으로 유도한 것이며 개별 화자의 크롭 이미지를
눈으로 비교한 것은 s01·s04 한 프레임뿐이다.

## 6. 부수 확인

**랜드마크 0·17 인덱스** — 2026-08-22 §5.4가 미검증으로 남긴 가정을 실측으로 확인했다.
MediaPipe 입술 40점을 링으로 복원하면 0과 17이 바깥 링 세로 중앙선의 유일한 두 점이고,
실제 프레임에서 0이 17보다 위다(s01 1306.0 < 1490.2, s06 799.0 < 886.2).
**§5.3의 6/152·0/152·2/152와 §5.4의 81%·9.5%는 무효가 아니다.**

**LIP_LANDMARKS 결손이 문서 기록보다 크다** — §5.1은 "윗입술 바깥 점이 없다"까지
적었으나, 실제로는 **바깥·안쪽 두 링 모두 아래 호만 있고 위 호가 통째로 없다.**
빠진 19점은 바깥 위 호 9점(185·40·39·37·0·267·269·270·409), 안쪽 위 호 9점
(191·80·81·82·13·312·311·310·415), 안쪽 왼쪽 입꼬리 78이다. 파일이
`UPPER_INNER_LIP = 13`을 선언해 놓고 목록에서는 13을 빼고 14만 넣는다.
그 결과 무게중심이 입술 높이의 **+19%** 아래로 치우친다(s01 +37.0px, s06 +18.0px,
2화자 2프레임 실측).

**다만 192x96에서 윗입술이 잘리지는 않는다** — 7화자(s01·s03·s04·s06·s07·s08·s09)
x 15문구 x 6프레임의 크롭 시트를 눈으로 확인한 결과, 윗입술 바깥 윤곽이 프레임 밖으로
나가는 사례가 없었다. 가장 심한 경우가 위 가장자리에 접하는 정도다. **무게중심 편향은
여백 배분의 문제이지 정보 소실이 아니다.** s02·s05는 로컬에 원본이 없어 미확인이다.

**저장 편향이 줄었다** — 저장값 − 마지막이 **+0.024**다. 이전 관측 0.037보다 작다.
`smoothing=3` 저장 기준이 효과를 본 것으로 보이나 규격도 함께 바뀌어 분리되지 않았다.

**학습 포화가 빨라졌다** — 중앙 35에폭(옛 기록 대비 이른 편)이고 이후 45에폭은
개선 신호 없이 돈다. 정점 위치는 전체의 24%~98%로 여전히 흩어진다.

## 6-2. 재현 잡음이 판정선과 같은 크기다

조건을 아무것도 바꾸지 않고 같은 화자·같은 시드를 다시 돌린 쌍이 넷 모였다.
`align` 3런(s01)과 `repro_192_s06_seed42`다. 전부 `deterministic=False`다.

| 화자·시드 | 1차 | 2차 | 차 |
|---|---|---|---|
| s01 seed42 | 0.484 | 0.446 | -0.038 |
| s01 seed1 | 0.688 | 0.650 | -0.038 |
| s01 seed7 | 0.459 | 0.471 | +0.012 |
| s06 seed42 | 0.624 | 0.637 | +0.013 |

```
평균 -0.013 · SD 0.029 · 폭 0.051
절대차 평균 0.025 · 최대 0.038
```

**최대 0.038로 판정선 0.042에 거의 닿는다.** 조건 효과와 재실행 잡음이 같은
크기라는 뜻이다. 2026-08-20 이후 판정이 계속 미확정으로 끝난 이유가 여기에 있다.

**마지막 에폭이 저장값보다 더 흔들린다.** s06 seed42에서 저장값은 0.624 -> 0.637로
+0.013 움직였는데 마지막 에폭은 0.580 -> 0.624로 +0.044 벌어졌다. 저장값은
3에폭 평균이라 평활 효과가 있고 마지막 에폭은 단일 시점이다. **보고 기준을
마지막 에폭으로 정한 결정(§7)을 다시 봐야 한다.** 저장 편향은 작지만 분산이 크다.

**조치** — `set_seed`의 `deterministic` 기본값을 켬으로 바꿨다. `train()`과
`run_experiment.py` 양쪽이다. cuDNN 밖의 비결정 연산은 이걸로 안 잡히므로
완전한 재현은 아니다. `torch.use_deterministic_algorithms`는 대체 구현이 없는
연산에서 예외를 던져 학습이 멈추므로 쓰지 않는다.

**아직 안 잰 것** — 결정성을 켠 쪽의 폭이다. 같은 칸을 두 번 돌려야 비교가
되는데 켬 쪽은 한 번도 없다. 노트북 §12의 재현성 확인 셀에서 `DETERMINISTIC = True`로
두 번 돌리면 된다(48분).

## 6-3. 옛 기준값이 셀에 박혀 있다

`base80`(셀 23), `BASE` dict(셀 46), 재현성 셀의 "기존 관측 0.809 / 0.739 / 0.822"
셋 모두 옛 규격(112x80 · base60)의 숫자다. cv192와 견주면 각각 -0.227, s01 -0.169,
s06 -0.185라는 가짜 낙폭이 나온다. 실제 cv192 값은 s01 0.544, s06 0.648이다.

셀에 기준값을 손으로 적는 방식이 원인이다. `run_experiment.py --baseline cv192`는
파일에서 읽으므로 이 사고가 안 난다. 새 실험은 러너를 쓴다.

## 8. 다음 회차 과제

1. **s05는 크롭으로 못 건진다** — 0.231 -> 0.269에 그쳤다. 확대(x1.31)를 없앴는데도
   이 정도면 원본 화질(720x1280, 유일한 1080p 미만)이 한계다. 재촬영 외의 방법이 없어 보인다
2. **s05 학습 제외 재측정** — 옛 결론(남기는 편이 낫다)은 112x80 시절이고 그 근거였던
   화질 문제를 새 크롭이 일부 고쳤다. `no5_192`로 시드 수를 맞춰 다시 잰다
3. **s01·s06이 왜 내려갔나** — 두 화자만 반대 방향이다. 계산으로 세운 가설 셋은
   §5대로 전부 기각됐고, 크롭 시트 육안 검사에서도 잘림은 원인이 아님이 확인됐다.
   남은 후보는 대비·해상감 쪽이다
4. **랜드마크 특징 40점 확장** — 노트북 §13의 보조 특징이 `LIP_LANDMARKS`를 그대로
   써서 **아래 호 21점만** 들어간다. 윗입술 윤곽 축이 통째로 없다. 단독 0.397 ·
   융합 -0.023이라는 기각이 "정보 부족" 때문인지 "윗입술 누락" 때문인지 갈린다.
   npy 재생성 없이 `aux40_f60.npz` 재추출만으로 잰다. 고칠 곳 셋:
   `AUX_DIM` 44 -> 82, 배율 정규화의 `P[:, 0] - P[:, 10]`을 입꼬리 61·291로 고정
   (순번 기반이라 목록이 바뀌면 조용히 다른 걸 잰다), 캐시 파일명 변경
5. **크롭 무게중심 편향 보정** — 우선순위 낮음. 잘림이 없음이 확인돼 이득이 여백
   배분 개선에 그치는데, npy 4.1GB 재생성과 기준선 단절이 따른다
6. **시간축 증강 60프레임 조합** — 2026-08-19b의 3순위 미실행 과제
7. **s07 턱 사용량 측정** — 2026-08-22 §4.2에서 넘어온 미측정 과제.
   전처리 트리밍은 정상임을 확인했다(15문구 원본의 55~89% 보존, 최소 고유 34프레임)

## 부록 · 재현 방법

```bash
python scripts/run_experiment.py --name cv192 --seeds 42 1 7 \
  --manifest <드라이브>/manifest_f60.csv --data-root <로컬>/data_f60 \
  --checkpoint-dir <드라이브>/checkpoints --wandb-project lipreading

python scripts/run_experiment.py --name cv192 --summary --baseline base60
```

`results/cv192.json`은 Colab 로컬에 쓰이므로 런타임이 끊기면 사라진다. 이 파일은
wandb 런 요약에서 옮겨 저장소에 넣은 것이다. `run_experiment.py`에 결과 경로 옵션이
없는 것은 미해결 과제다.
