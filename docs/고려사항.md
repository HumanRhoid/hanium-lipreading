# 추가 고려사항 · 리스크

설계서(`한이음_립리딩_설계.md`)에 더해, 진행 내내 의식해야 할 점들.

## A. 데이터 · 법 · 윤리
1. **AI Hub 라이선스** — 데이터/파생물 재배포 제한 가능 → GitHub 커밋 금지, 레포는 **비공개(private)** 권장.
2. **얼굴 = 개인정보/생체정보** — 자체 녹화는 **촬영·활용 동의** 받고, 얼굴 공개 금지·익명화. 한이음 서식도 "개인정보 기재 x".
3. **의료 도메인 책임** — 환자용 의사소통 도구의 오인식은 위험("아파요"를 놓치면?) → **신뢰도 임계값 + '불확실' 표시 + 사람 확인**을 전제로 설계.

## B. 기술적 함정
4. **평가 현실성** — 같은 사람으로 학습·테스트하면 정확도가 부풀려짐 → **화자 분리(speaker-independent) 평가 필수.** 데모 정확도 ≠ 실제 환자 정확도.
5. **폐쇄형 한계 + 거부 클래스** — 고정 N개 밖은 표현 불가. **'해당 없음(none)' 클래스**를 둬 억지 추측 방지. 문구 선정은 실제 환자/AAC 수요 반영.
6. **도메인 갭** — 실제 환경(누운 자세, 마스크/튜브, 어두운 조명)과 학습 데이터 차이 큼 → 데모 조건 통제 + 한계 명시.
7. **모델 크기 vs 실시간** — 클수록 정확하나 느림. 실시간(P3) 단계엔 경량화 트레이드오프.

## C. 협업 · 운영
8. **체크포인트·데이터는 git 밖** — 가중치(.pt)·영상은 드라이브/Releases로. git엔 코드·설정·문서만.
9. **재현성** — 시드 고정, requirements 핀, manifest로 데이터 버전 관리.
10. **성공 기준 수치화** — "잘 된다" 대신 "N개 문구 화자분리 top-1 ≥ 목표%"처럼 못 박기.
